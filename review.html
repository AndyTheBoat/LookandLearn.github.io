YouTube reviewer guide

Current status: prelaunch proof of concept, no real customers. This public static demo demonstrates the independent-question interaction. YouTube Data API search is proposed and not implemented here. No quota approval is claimed.

Purpose and value

Children choose what to watch; parents choose what to practise. Questions are independent of video content. Stop and Learn aims to give parents a practical reason to permit and encourage YouTube viewing within a learning routine, while preserving the learner’s interests and exposure to creators. This proposed benefit for YouTube needs pilot validation.

How to review

  1. Open the demonstration; no login is required.
  2. Select multiplication or vocabulary and a 15-second review interval.
  3. Paste an embeddable YouTube link or use the clearly labelled sample.
  4. Read the privacy notice, select the adult-review consent checkbox and load the video.
  5. Press Play using YouTube’s controls. Wait for the timed question or use the manual question button.
  6. Answer in the separate panel. A correct answer immediately resumes playback. For an incorrect answer, observe the sample answer and select Continue video. Native player controls remain available.
  7. Change the question set while keeping the video: this demonstrates the independence of learning goals.

If YouTube blocks embedding or the browser blocks the player, try a different permitted link. No restriction is bypassed. No live search interface is presented as functioning.

Architecture

The diagram distinguishes current link-based selection from the proposed search gateway. Playback controls use the IFrame Player API; they do not create Data API search requests. This public demo has no backend. The separate local prototype uses Django, PostgreSQL, assigned question lists and local speech recognition; those systems are not hosted on GitHub Pages.

Efficient API usage — proposed design

  • Search only when the user submits a query, never on each keystroke.
  • Merge identical simultaneous requests, bound retries and avoid unnecessary pagination.
  • Retain the chosen video ID for playback; questions and continuation need no further search.list calls.
  • Measure upstream calls, extra pages, retries and peaks before claiming savings.
  • Use one approved integration, with no project rotation or quota sharding.

The demo makes no search.list calls. These controls are a design to implement and measure, not existing production evidence.

Review boundaries and launch requirements

This demo uses fictional question sets and transient browser counts. It does not show real parental accounts, stored learning history, search discovery, production authentication or validated learning outcomes. Production operator details, ages/countries, consent, child-directed API notification, retention/deletion controls and backend security remain to be finalised. This public page enables review of the concept; it does not guarantee that YouTube will accept a reduced demo or approve quota.
